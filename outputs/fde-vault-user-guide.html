Chapter I Installation & First Launch

Forward Deployed Engineers operate directly inside client infrastructure where speed, discretion, and operational hygiene are paramount. Setting up FDE-VAULT requires zero external dependencies, no administrator privileges, and exactly one terminal command.

1. One-Line Automatic Installation

Run the official installer for your operating system. It downloads the engine, registers the global fde shortcut, configures shell profiles, and mirrors the skill into your AI coding harnesses:

Windows PowerShell (Command Prompt or PowerShell)

irm https://raw.githubusercontent.com/aryamanm77/fde-vault/main/install.ps1 | iex

macOS & Linux (Zsh or Bash)

curl -fsSL https://raw.githubusercontent.com/aryamanm77/fde-vault/main/install.sh | bash
What the Installer Configures
The installer executes idempotently: it places the application into ~/.fde-vault-app, registers the global fde CLI shortcut into your shell profile ($PROFILE, ~/.zshrc, or ~/.bashrc), mirrors the skill suite to ~/.claude/skills/fde-vault/ and ~/.agent/skills/fde-vault/, and configures permissions in ~/.claude/settings.json.

2. Master Passphrase & Session Security

FDE-VAULT protects client ledgers using salted PBKDF2-HMAC-SHA256 password hashing (100,000 iterations). Raw credentials and passphrases are never stored in plaintext and never leave your local CPU.

When you first launch the app by typing fde in your terminal: 

fde
  1. The kinetic startup emblem materializes on your console.
  2. You are prompted to enter and confirm your master vault passphrase (minimum 8 characters).
  3. An 8-hour authenticated local session token (.session-unlocked) is minted in ~/.fde-vault/.
  4. All AI coding tools (Claude Code, Antigravity, Cursor) now share this unlocked ledger without prompting for passwords in chat.
Zero-Chat-Exposure Rule
Never enter your master passphrase into an AI chat window. Always unlock via fde in your local terminal. If your session expires, typing fde lock will instantly seal it, and fde will prompt to unlock.

Chapter V Zero-Chat-Exposure Security Pipeline

The central vulnerability of terminal AI agents is accidental credential leakage. Engineers copy-paste API tokens, customer database connection strings, or personal data into chat, exposing secrets to model training and cloud telemetry. FDE-VAULT eliminates this completely.

1. Local CPU Secret Redaction (No Cloud Exposure)

FDE-VAULT features a local, CPU-side regex scrubbing pipeline in vault_guard.py that scrubs 18+ enterprise secret formats before text leaves your machine:

  • AWS Access Keys (AKIA...) & GitHub Personal Access Tokens (ghp_...)
  • Stripe API Keys (sk_live_...) & Slack Tokens (xoxb-...)
  • RSA / OpenSSH Private Keys (BEGIN PRIVATE KEY)
  • Bearer JWT Tokens & Database Connection Strings (postgres://...)
  • Personal PII: Credit card numbers, Social Security Numbers, and email addresses

2. Safe Ingestion Commands

Ingest from Host Clipboard Directly

fde ingest --clipboard

Reads your clipboard, scrubs all detected credentials into safe tokens (e.g. [REDACTED:AWS_KEY]), appends clean text to inbox.md, and clears the clipboard.

Ingest from File and Securely Shred

fde ingest --file sensitive-notes.txt --wipe

Scrubs the file into inbox.md, then performs a 3-pass DOD-standard secure file shredding overwrite before unlinking the source.

3. Active Terminal Firewall Hooks

When running inside Claude Code, .claude/settings.json activates two hooks:

  • UserPromptSubmit (Prompt Firewall): Inspects every message you submit in chat. If you accidentally paste a credential, the hook intercepts the submission locally and rejects it before it reaches the network.
  • PreToolUse (Tool Guard): Verifies that any file read, write, or bash operation is gated by an active vault session.

Chapter VI Step-by-Step Field Engagement Lifecycle

Here is the exact lifecycle of an FDE engagement using the everyday commands, from the first discovery call to final client offboarding:

Phase 1: Day 1 — Kickoff & Account Provisioning

  1. Start Your Day: Unlock your session: 
    fde
  2. Select or Create Account: Mount the customer ledger in AI chat: 
    select client-enterprise
  3. Run Discovery Interview: Generate the technical questionnaire: 
    setup
    Answer the questions with customer architects to establish mission, systems, and constraints.

Phase 2: Days 2–10 — Scoping & Architectural Guardrails

  1. Ingest Meeting Notes: Paste raw notes via clipboard without exposing secrets: 
    fde ingest --clipboard
    Then in AI chat, process them into the ledger: 
    notes
  2. Guard Against Scope Creep: When customer stakeholders request extra features: 
    check-request "Add support for real-time Kafka streaming"
    FDE-VAULT evaluates the request against brain.md and drafts a diplomatic response.
  3. Pre-Flight Architectural Check: Before committing code changes: 
    check-code "Add Redis caching bypass around core auth service"
    Evaluates the proposal against Rule 01–05, flagging core hacks vs. edge adapters.

Phase 3: Days 11–20 — Production Delivery & Incident Triage

  1. Incident Response: If an outage or deployment failure occurs: 
    issue "Memory leak in background sync worker on Kubernetes"
    Logs the incident, assigns severity, identifies root causes, and creates containment steps.
  2. Upstream Proposals: If an architectural change requires customer core team buy-in: 
    proposal "Dedicated Webhook Consumer Queue"
  3. Leadership Briefing: Generate a 1-page executive brief for stakeholders: 
    summary

Phase 4: Day 21 — Handover & Hardcover Book Generation

  1. Generate Handover Runbook: Complete the engagement: 
    finish
    Compiles outputs/handoff-runbook.md, pitch deck, and compiles outputs/dashboard.html.
  2. Interactive Hardcover Book: Open outputs/dashboard.html in any browser to review your complete engagement as a page-turning archival book.
  3. Seal the Session: Lock down your vault: 
    lock
